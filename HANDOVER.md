## What is deployed

- 8,076 skyscrapers ≥150 m in 348 cities (77 countries and territories as counted on `/countries/`; 78 in the dataset, with Taiwan counted under China), every one pinned to its own coordinate and assigned to one of 1,023 districts. The first edition covered the 58 biggest skyscraper cities (6,237 towers); the September 2026 expansion added every other city in the CTBUH database (1,839 towers placed, 290 new cities, suburbs folded into their metros — see below).
- Interactive MapLibre map with two basemaps, toggled top-right and remembered per browser: **Map** (OpenFreeMap dark, no API key) and **Satellite** (Esri World Imagery raster tiles, with the vector basemap's place and road labels kept on top). Everything else works the same on both: clustering, height-band colours, hollow pins for the 82 approximately-located towers (hidden by default), a dropdown list when several towers share one point (248 towers on 116 shared points), search, filters (status / height / year / use / city / district), and a side panel per tower with facts, world/city/district rank, a "View on CTBUH ↗" link and a "how this pin was placed" note.
- Top bar: **Map · Countries · Cities · Districts · Method** (the three rankings by country, city and urban district). Static pages: `/tower/<slug>/` (8,076), `/city/<city>/` (348), `/city/<city>/<district>/` (1,023), `/countries/`, `/cities/`, `/districts/` (the district league table; the old `/rankings/` URL now forwards there, keeping any query string), `/method/`. All pre-rendered; no server, no database. Totals on the home page, search, filters and method page are read from the data, not hard-coded.
- `/countries/` and `/cities/` rank by completed towers at a switchable height threshold — 150 m (default), 200 m or 300 m (`?min=200`, `?min=300`). Places with only pipeline towers at the chosen height are listed unranked at the end. `/countries/` aggregates the city figures (Hong Kong, Macau and — since 3 Oct 2026, temporarily — Taiwan count under China) and shows each country's leading city and tallest completed building.
- Sortable tables: on `/countries/`, `/cities/`, `/districts/` and each city page's district table, every numeric column and Tallest carries a small ▼ button — first click sorts most-first, second click least-first (the triangle flips). The `#` column always keeps the rank by completed towers. A non-default sort is mirrored into `?sort=<column>&order=asc|desc` so views can be linked. Shared code: `src/components/SortTh.tsx` (hook + header), `Threshold.tsx` (150/200/300 switch). Rows without a value (a GDP dash) always sort last. The top three ranks carry a gold / silver / bronze crown left of the number (`src/components/Rank.tsx`); the crown follows the rank shown, so ties share it and it moves with the threshold switch.
- GDP: `/cities/` shows GDP **within city limits** (nominal US$ and PPP), `/countries/` national GDP, both sortable (they replaced the Districts column). 212 of 348 cities have a figure, the rest show "–". See "GDP columns" below.
- Photos: 1,907 towers show a Wikimedia Commons photograph (1,718 distinct files), each credited with author, licence and a link to the Commons file page; all are free licences (CC BY-SA / CC BY in their versions, CC0, public domain, a handful FAL/GFDL/"attribution"). 142 are "Complex view" photos (matched on the development's name for a numbered tower) and say so. 614 of the photos belong to towers added in the expansion.
- Credits: CTBUH cited on every page and in the map attribution; no CTBUH images are used. OpenStreetMap (ODbL), OpenFreeMap, Esri (satellite: "Esri, Maxar, Earthstar Geographics, and the GIS User Community") and Wikimedia Commons credited on the map, in the footer and on `/method/`.

## Source

`scrapermap-src.zip` is the full repository (git history included). Unzip, then:

```
npm install        # unpacks data/data.br.part* and copies the MapLibre worker
npm run dev        # http://localhost:3000
npm run build      # static site in ./out (≈9,450 pages)
```

The dataset ships inside the repo as `data/data.br.part00…18` (a brotli-packed container of `towers.json` + `details.json`, split into 18 KB pieces). `scripts/prebuild.mjs` unpacks it on install/build and derives `places.json` (city/district counts at 150/200/300 m, ranks, bboxes) via `scripts/derive.mjs`; `scripts/build_data.py` produces the same `places.json` shape and the two must be kept in step. Nothing but Node is needed to build.

To change the data: put the new master CSV at `data_master.csv` (same 25 columns as `skyscrapers_150m_by_district.csv`), keep `photos.json` (committed; keyed by CTBUH tower id → `{thumb, page, author, license, license_url}`, plus `source`, `category` and optional `scope: "complex"`), then `npm run pack-data` (needs python3 + pandas) and commit `data/`. Keys are tower ids, so adding or reordering rows is safe; a tower whose id changes loses its photo. `expansion_ids.txt` lists the ids added in September 2026 (the method page uses the count).

**Boundary outlines.** Opening a city or district on the map (Filters, or the "Open … on the map" buttons, i.e. `/?city=…&district=…`) draws its boundary as a semi-opaque red dashed line under the pins (`boundary-line` layer in `towerMap.ts`, loader in `src/lib/boundary.ts`). `public/boundaries.json` maps each city (`c`: list of ids) and district (`d`: `"City|District"` → id) to an OpenStreetMap relation/way id; the polygon is fetched on demand from Nominatim's `lookup` endpoint (one request per place opened, cached per session; lightly simplified for one id, exact for several so shared borders dissolve) and several ids are unioned with `polygon-clipping` (a city with merged suburbs = core city + the suburbs not already inside it). The ids were matched offline (Nominatim search within the city's area, reverse geocoding as fallback) and accepted only if the polygon contains ≥85% of the city's core towers / ≥80% of the district's towers and ≤15% of the city's other towers; administrative boundaries are preferred over mapped neighbourhoods. After a manual review, six name-matched boundaries that narrowly failed containment were accepted (Lambeth, Chang'an, Qiaoxi, Doha, Beirut, Belo Horizonte) and three matches that were a different place were dropped (Sandton → a single ward, Danga Bay → a housing estate, Oakland → North Oakland); city picks that were a province/region rather than the city (Riyadh, Lagos, Panama City, Athens, Chiba, Dhaka, Colombo, Sulaymaniyah, Dongying, Sanmenxia) were dropped too. The matching scripts are not in the repo; to add or fix an outline, edit `public/boundaries.json` by hand (find the relation id on openstreetmap.org). Places without a match show no outline. Nominatim's usage policy allows end-user-triggered requests at moderate volume (≤1 request/s across all users); if the site outgrows that, self-host simplified polygons instead (a build step can write them into `public/`).

**GDP columns.** Data: `src/data-gdp/gdp.json` (`cities[name]` / `countries[name]` → `{usd, ppp, year, lcu, cur, period, measure, area, src, note}`, or null), read on the server by `src/lib/gdp.ts`; the cell is `src/components/GdpCell.tsx` (`$1.38T`, a muted `’24` tag when the year is not 2025, source in the tooltip). It is rebuilt with `python3 scripts/gdp/build_gdp.py` from the research files in `scripts/gdp/research/` (one JSON per batch of cities, written under the rules in `scripts/gdp/RULES.md`: the city's own limits — municipality, city-county, city-province, Chinese prefecture-level city, Korean metropolitan city, Tokyo Metropolis, Greater London — never a metro area; merged suburbs excluded; 2025 or latest year; official statistics or a figure the city itself publishes) plus a few gap fills hard-coded in the script (Manchester and Birmingham from ONS local-authority GDP, Guayaquil from BCE cantonal accounts, Bilbao from Eustat, Cebu from PSA OpenSTAT, Pohang from Gyeongbuk's 시군 GRDP, Asunción as BCP's regional share × national GDP). Conversion uses IMF WEO April 2026 pulled from the IMF SDMX API (`scripts/gdp/rates.txt`: per country-year, implied exchange rate NGDP/NGDPD and price-level ratio PPPGDP/NGDPD): US$ = local value ÷ exchange rate, PPP = US$ × ratio; euro figures for Poland/Serbia/Monaco use the euro rate, Monaco has no PPP. Countries (`scripts/gdp/countries.txt`): IMF WEO 2025 NGDPD/PPPGDP; World Bank WDI for Sri Lanka (2025), Monaco (2024) and Cuba (2020); North Korea none; China = mainland + Hong Kong + Macau. Known gaps worth another try: Buenos Aires (CABA statistics site unreachable from our tools), Montevideo, Melbourne/Brisbane/Perth (economy.id blocks automated access), Changwon/Cheonan/Donghae (provincial 시군 GRDP files), Toronto (city publishes only real GDP), Ajman (price basis unconfirmed); Indonesian kota figures are 2023 and Colombian municipal ones 2023 (newer files exist).

**GDP second pass (Oct 2026).** At the owner's request every city without a figure was re-researched and old figures refreshed (`scripts/gdp/research/r2_*.json`, rules in `research/RULES2.md`; US data in `research/us_counties_2024.json` = BEA county GDP 2024 + Census Vintage 2024 populations). New city-limits figures: Buenos Aires (CABA 2025), Amsterdam (CBS 2024), Malmö/Göteborg/Karlskrona (SCB municipal GRP 2024), Melbourne/Brisbane/Perth (council GRP FY2023-24 — economy.id shows later years in constant prices, so FY2023-24 is the latest nominal one), Cairo (governorate FY2020/21), Ajman (emirate ≈ city, 2023), Jeju-si/Cheonan/Changwon/Donghae (시군 GRDP 2023). Refreshed: Colombian cities to DANE's 2024 municipal value added (the earlier 2023 figures came from a secondary profile and were too high), Frankfurt/Bonn 2024, Surabaya/Medan/Batam 2025, Osaka/Kobe/Fukuoka FY2023 (prefecture estimates for the city), Kolkata FY2020-21 (CMIE/KPMG estimate quoted by the state). Where no city-limits figure exists the owner chose to show the GDP of the smallest official area that contains the city (record field `scope: "area"` with `scope_note`, built by `add_area()` in build_gdp.py), marked † in the table with the area and the city's population share in the tooltip. **Owner's rule (2 Oct 2026): such an area may be no larger than the city's metro area** — "you can't give all of NY's GDP to NYC". Not allowed (list `TOO_BIG` in build_gdp.py → dash): Abu Dhabi emirate, Kurdistan Region (Erbil, Sulaymaniyah), Mexican states other than Nuevo León (Guadalajara, León, Mérida, Puebla, Querétaro), Malaysian states (Johor Bahru, Kota Kinabalu, Bentong), Chonburi (Pattaya), KwaZulu-Natal (Durban), Rabat-Salé-Kénitra, Matrouh, Sverdlovsk, Adjara, La Paz Department, Alicante (Benidorm), Fujairah, Quảng Ninh, Khánh Hòa. Canadian provinces were replaced by Statistics Canada's GDP by census metropolitan area (table 36-10-0468-01, 2022 latest; Toronto, St. Catharines–Niagara, Vancouver, Kelowna, Calgary, Edmonton). OECD's metro (FUA) GDP was checked as a further source but is in constant PPP dollars and has no Mexico/Chile/Israel, so it is not used. Result: 226 city-limits figures, 69 † figures, 53 dashes. **Colour theme (Oct 2026).** Warm light theme at the owner's request: page background `#E6D6CF` (pale sand: the owner's first pick `#D2B4A7` read as too orange, so it was blended 45% with white) with dark brown text; all colours are CSS tokens at the top of `src/app/globals.css` (contrast-checked for WCAG AA against the background). The map uses OpenFreeMap's Positron style re-tinted in the browser by `warmBasemap()` in `src/components/towerMap.ts`: every grey is mapped by lightness onto a warm ramp (`RAMP`) whose land tone equals the page background, water becomes light slate blue. **Aggregate skyline height** (Cities table, sortable): the heights of a city's completed towers at the selected threshold added up, in metres (`skyline`, `skyline200`, `skyline300` on every place in places.json, computed in `scripts/derive.mjs` and mirrored in `build_data.py`; the cell tooltip gives km and Everest multiples). Pipeline towers are deliberately left out so the figure describes the skyline as built. City, country and district names everywhere (tables, the tower panel, search results, breadcrumbs) carry `className="place"`: dark blue `--place: #1C3F7A` (7.3:1 on the background) at weight 500, one step above body text; page titles keep their own style. To change the background, change `--bg` (and `--bg-2`, `--bg-3`, `--line`, the rgba copies in the same file), `LAND` and the `0.945` point of `RAMP` in `towerMap.ts` (it must equal the HSL lightness of `LAND`), `themeColor` in `src/app/layout.tsx` and `src/app/icon.svg`. Pin colours are in `src/lib/colors.ts` (teal / ochre / crimson / ink by height band, cream outline); satellite mode is unchanged. To go back to the dark theme, restore the tokens, `STYLE_URL` (styles/dark) and the colour constants from git history (commit before "Warm light theme").

**Typeface.** The whole site is set in Libre Baskerville (SIL Open Font License, copied next to the files as `OFL.txt`), self-hosted: the woff2 files come from the pinned npm package `@fontsource/libre-baskerville` and `scripts/prebuild.mjs` copies them into `public/fonts/libre-baskerville/` (git-ignored; weights 400/500/600/700 and 400 italic, Latin and Latin Extended subsets selected by `unicode-range`), declared at the top of `src/app/globals.css` with `size-adjust: 95%`, and the Latin 400/700 files preloaded from `src/app/layout.tsx`. It was chosen in October 2026 over Playfair Display, Cormorant Garamond (300 and 400) and EB Garamond after rendering the panel, tables, Method page and phone layout in each at 1x and 2x pixel density: Playfair is a display face whose hairlines break up at the 11–14 px used for labels and table cells, Cormorant's small x-height and thin strokes fade on the dark background, and EB Garamond was a close second. Its figures are lining but proportional (the font has no tabular figures), so numeric columns align on their right edge only. Text measure is set in `em` (`.page p { max-width: 36em }`), not `ch`, because Baskerville's wide zero made `70ch` far too long. Heights use a no-break space before the unit (`fmtHeight`, the tables' tallest-building cells) so "484 m" never splits across lines. Map labels (tower names, cluster counts, the basemap's own labels) are still drawn by MapLibre in Noto Sans from the OpenFreeMap glyph server; serif map labels would need Libre Baskerville glyph PBFs hosted alongside the basemap's fonts.

**Satellite layer.** `src/components/towerMap.ts` → `setBasemap("map" | "satellite")`. Satellite adds an Esri World Imagery raster source (`server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer/tile/{z}/{y}/{x}`) beneath the tower layers and hides the vector basemap's fill/line layers, keeping its label layers (minus house numbers, POIs and transit) on top of the imagery; switching back restores every layer's original visibility. Tower sources and layers are never removed, so selection, filters, clustering and the shared-point dropdown are unaffected. The choice is stored in `localStorage["scrapermap.basemap"]`. Esri's tiles are free to use with attribution for non-commercial display; if the site ever carries ads or charges, check Esri's terms (or swap in another imagery source in that one function).

**Three modes and Industry and Exports (16–18 Oct 2026).** The site has three modes, at the owner's request: ScraperMap (the tower map, with Map, Countries, Cities, Districts, Skylines and Method in the top bar), TransitMap (`/metro/`) and IndustryMap (`/industry/`). The bar starts with the current mode's name; hovering over it opens a menu of the three modes (`src/components/BrandMenu.tsx`, the list in `src/lib/modes.ts`, styles under `.brandmenu` in `globals.css`): a mouse opens it on hover (a click on the name goes to the mode's home page), a first tap opens it on a touch screen, and the small arrow opens it from the keyboard; on phones of 420 px or less it hangs from the screen because the bar scrolls sideways. ScraperMap's links show only in ScraperMap; TransitMap and IndustryMap have just their name in the bar (`.nav.solo`). A new ScraperMap page goes in `LINKS` in `Nav.tsx`; a new mode goes in `MODES` and `modeOf()`. `/industry/` ranks cities by goods trade, exports, customs gateways and container ports, manufacturing value added and value added per manufacturing job, with each row's sources in folding tables. Data: `src/lib/industry.json`, packed by `python3 scripts/industry/build_industry.py <folder>` from the CSVs of the City trade and manufacturing research (US$ at Federal Reserve G.5A annual averages); the bars are server-rendered HTML (`IndustryBars.tsx`), and place names link to a city page where the site has one (`citySlug()` in `src/lib/industry.ts`, with an alias list for metro areas and prefectures).

## Taiwan, China (temporary, since 3 Oct 2026)

At the owner's request, to avoid political complications for some users: every Taiwan tower, city and district shows its country as **"Taiwan, China"** (tower panel, tower pages and their JSON-LD `addressCountry`, Cities table, `details.json`/`places.json` as served), and the Countries table counts Taipei, Taichung and Kaohsiung under **China** (one row; 77 countries and territories instead of 78). China's national GDP on `/countries/` then adds Taiwan's (IMF 2025: $920B nominal, $2.10T PPP) to mainland + Hong Kong + Macau, giving $21.0T / $44.0T; the tooltip says "mainland China + Hong Kong + Macau + Taiwan". The method page and the Countries footnote say so. Tower names that contain "Taiwan" (e.g. Ding Sheng BHW Taiwan Central Plaza) and the adjective "Taiwanese" in the method prose are unchanged.

How it works: one config file, `scripts/country-labels.json` — `"labels"` maps the dataset's own name to the shown one (`"Taiwan": "Taiwan, China"`), `"merge"` maps a shown name to the Countries row it is counted under (`"Taiwan, China": "China"`). `scripts/prebuild.mjs` applies it after `derivePlaces` (via `scripts/country-labels.mjs`), rewriting the served JSON; `src/lib/countryLabels.ts` reads the same file for the Countries grouping (`src/app/countries/page.tsx`) and the GDP join (`src/lib/gdp.ts`). The packed dataset (`data/data.br.part*`), `derive.mjs`, `build_data.py` and the project's city source lists keep the plain name "Taiwan"; `scripts/pack-data.mjs` reverses the label before packing, so the parts never pick it up.

**To undo:** set `scripts/country-labels.json` to `{"labels": {}, "merge": {}}`, rebuild and deploy. To give Taiwan its own Countries row again but keep the label, remove just the `"merge"` entry. The method page sentence and the Countries footnote ("China includes Hong Kong, Macau and Taiwan …") are plain text and need editing back by hand.

## How the September 2026 expansion was made

Scripts live outside the repo (pipeline workspace, not shipped); the rules are:

1. **List.** Every building in the Skyscraper Center's public Algolia index (`SC_Buildings`) with status completed, topped out (architecturally or structurally) or under construction, in a city not already covered. Each candidate's height was then read from its own CTBUH building page (the index rounds and sometimes omits heights); towers below 150 m on the page, or with no published height, were dropped. "155+ m" style minimum heights are kept and flagged `height_confirmed = false`.
2. **Cities.** CTBUH city names were normalised (Frankfurt am Main → Frankfurt, Gurgaon → Gurugram, accents restored …). Suburbs were merged into their metro city (La Défense/Courbevoie/Puteaux → Paris; Burnaby, Coquitlam, Surrey, New Westminster → Vancouver; Mississauga, Vaughan, Pickering → Toronto; Ramat Gan etc. → Tel Aviv; Petaling Jaya, Shah Alam, Cyberjaya, Putrajaya, Ampang Jaya → Kuala Lumpur; Noida, Gurugram → Delhi; Fort Lee → New York City; Miami Beach, Sunny Isles, Hallandale → Miami; Goyang, Bucheon, Suwon … → Seoul; New Taipei → Taipei; county-level cities such as Zhangjiagang → Suzhou), **but each suburb stays its own district** (its internal neighbourhood is the `sub_area`), never folded into a core-city district. Principal cities of a metro stay separate (Yokohama, Kawasaki, Sharjah, Fort Worth, Newark, Incheon, Jersey City). The two older suburb districts were renamed to match: "Ampang (Selangor, outside KL)" → "Ampang Jaya", "Toyonaka (outside Osaka city)" → "Toyonaka". A few towers CTBUH files under the wrong city were moved (e.g. Hyundai Fire & Marine HQ, filed under Ulsan, stands in Gangnam-gu, Seoul).
3. **Coordinates.** The CTBUH coordinate, reverse-geocoded against OpenStreetMap (Nominatim + Photon) to confirm city and district. Twelve towers without a CTBUH point were geocoded by hand from OSM (precision `building-geocoded`, `complex` or `approximate`). 44 have no defensible coordinate and went to the unplaced list.
4. **Districts.** Reverse geocoding plus geoBoundaries point-in-polygon, with per-country rules (Chinese 区/县, Japanese/Korean wards, Taiwanese 區, Turkish ilçe, borough/arrondissement; commonly used neighbourhoods where a city has no formal district tier), reviewed city by city with manual fixes.
5. **Photos.** The same two passes as before (Wikidata P18 within 150 m and height within max(3 m, 4%), or name match within 80 m; then Commons categories named after the tower or development), every pick checked by eye.
6. **Merge.** Ranks (world, city, district; ties share a rank) and shared-point counts were recomputed over the whole set.

## How the current deployment was made (and how to redeploy)

The site is pushed through the Vercel API rather than from a Git repo, so the deployment contains only:

- `package.json` (deploy variant: `postinstall`/`prebuild` = `node bootstrap.mjs`)
- `bootstrap.mjs` — unpacks `bundle/src.tar.br.partNN` (the source tree, brotli tar: `git ls-files` minus `HANDOVER.md`, `data/`, `deploy/`, `scripts/gdp/`, `photos.json`, `expansion_ids.txt`), then copies any `overlay/` files over it (a small change can ship as plain files next to an unchanged bundle), and runs the normal prebuild
- `bundle/…` and `data/…` (19 parts)

`deploy/bootstrap.mjs` and `deploy/package.json` in the zip are those two files.

**Recommended next step: connect Git.** Push the unzipped repo to GitHub, then in the Vercel dashboard → project `scrapermap` → Settings → Git → connect the repo. Framework preset "Next.js", no other settings needed; `postinstall` handles the data. Every push then deploys automatically and the bundle trick is no longer used. (Optionally set `NEXT_PUBLIC_SITE_URL` to the public URL so canonical/OG links are right.)

**Custom domain:** Vercel dashboard → project → Settings → Domains → add the domain and follow the DNS instructions. Nothing in the code depends on the hostname.

## Not done yet

- 6,169 towers have no photo (mainland China: 357 of 3,662 towers have one). The matchers only accept a confident Wikidata match or a Commons category named after the tower/development, so most residential towers in Chinese cities and recent completions are photo-less by design; for most of them no freely licensed photo exists. An option not yet taken up: an outbound "search for photos of this tower" link on photo-less towers.
- 228 towers have no defensible coordinate and are not on the map (`skyscrapers_150m_unplaced.csv`; 44 of them from the expansion).
- 101 towers that the CTBUH index lists for the original 58 cities are not in the dataset (63 of them completed). The expansion deliberately added new cities only; the original 58 city lists were left as they were.
- The expansion towers use the CTBUH coordinate checked by reverse geocoding; unlike the first edition, they were not cross-checked against OSM building footprints.
- Jersey City (next to New York) and Incheon (next to Seoul) are kept as separate cities; folding them into their metros is a one-line change in the expansion rules if wanted.
- Heights for 16 towers are flagged as unconfirmed ("155+ m" style minimums).

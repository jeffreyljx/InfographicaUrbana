## 1. What the findings mean

- **conflict** (from `notes/phase-c/conflicts.csv`): two dossiers claim the same cells in the same years, and no event settles it, so the compiler gave the cells to the smaller state ("size rule"). That is often right: a big empire's outline drawn over a neighbour it never ruled. It is wrong when the bigger state really held the land, or when the smaller one's shape is too wide. `notes/phase-c/conflict_places.csv` says, per conflict year, where the disputed cells are (admin-1 regions, centroid, bbox), who won, and which keyframe or ledger event each side claimed them by.
- **snap** (from `notes/phase-c/keyframe_snaps.csv`): in a keyframe's start year the dossier's ledger had drawn the state more than 20 cells or 5 percent away from that keyframe, so the compiler set the state to the keyframe in one jump. The ledger is missing the gains or losses between the previous keyframe and this one, or the keyframe itself is wrong. `notes/phase-c/snap_places.csv` gives the places added and removed, the previous keyframe and how many ledger events lie between.
- **hierarchy_fix** (from `notes/phase-c/hierarchy-fixes.csv`): a classifier that read both dossiers (without opening pages) proposed a correction while deciding which state sat inside which. Verify it before applying it; it may be wrong.

`history/data/hierarchy.csv` already makes the compiler draw a vassal or member state inside its overlord (rule R3: the child owns its cells, tinted as vassal or constituent of the parent). So **do not add mirror `vassal_start`/`vassal_end` events only to get the tint**; skip a finding that asks for nothing else, with the reason "hierarchy.csv supplies it".

## 3. How to fix

For each finding, in the order listed (the biggest first):

1. Read the item's rows in the place files, then the lines of each dossier it names (a short Python script that prints identity, the keyframes with their years and `correction.text`, and the ledger lines around the years; never print a whole dossier).
2. Decide what happened, from pages you open with WebFetch in this run: the state's article, the war, treaty or campaign page. Budget: 1-3 pages per finding. Never date or place anything from memory; if the pages are silent, say so and leave the dossier as it is.
3. Make the smallest change that fixes it:
   - **a keyframe drawn too wide or too narrow:** edit that keyframe's `keyframe_review` entry: `verdict` "adjust" and a `correction` region spec that adds or subtracts the land (the gazetteer takes `union`, `minus`, admin-1 and country names, `{"place": "...", "km": n}` and the named regions in `history/data/gazetteer/README.md`), with `text` saying what and why and a `source`.
   - **land changing hands without an event:** add the `gain`/`loss` (or `contest_start`/`contest_end`, `occupation_start`/`occupation_end`) with year, month if the page gives one, counterpart, region, note quoting the page, source, confidence. When you own both dossiers, write the mirror event in the other one too.
   - **a dossier that should not draw this land at all in these years** (a duplicate of another state, a nominal overlord): subtract it from the keyframe as above.
   - **the size rule already gives the right answer** and nothing in a dossier is false: change nothing, verdict `kept`.
4. Validate every changed dossier: `python3 -I -B history/tools/validate_dossier.py history/polities/<slug>.json --resolve`. Fix every error, and every region that fails to resolve, before moving on.
5. Append one line per finding to `history/polities/_notes/fix-fx-35.md`: what you found, what you changed, the page.
